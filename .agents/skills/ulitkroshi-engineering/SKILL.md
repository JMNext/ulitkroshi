# Инженерные стандарты и архитектура проекта «Улиткроши»

> **Назначение:** Закрепление архитектурных решений, версий компонентов, правил безопасности и критериев готовности (Definition of Done) для детской игровой PWA «Улиткроши».

---

## 1. Базовые архитектурные правила и стек

Любое изменение стека или базовых библиотек требует **ADR (Architectural Decision Record)** с обоснованием, фиксацией рисков и согласованием с Заказчиком.

| Слой | Утвержденный стек | Ключевые ограничения |
| :--- | :--- | :--- |
| **Frontend UI** | React 18+, TypeScript 5.x, Vite 5+, Zustand 4+, Axios | Строгая типизация, Tailwind CSS v4, адаптивность под мобильные экраны (100dvh, Safe Area). |
| **Игровой движок** | Phaser 3.x (2D Canvas / WebGL) | Только Phaser 3 API. Полная изоляция от React UI и роутинга. Обмен через сторы/EventBus. |
| **Backend API** | Node.js 22 Alpine, Express 4.x, `tsx` | Монолитная структура с изоляцией контекстов: `auth-service`, `game-service`, `shared`. |
| **База данных** | PostgreSQL 17, пул `pg` | Никакого DDL в рантайме. Миграции up/down, атомарные транзакции, индексы. |
| **Инфраструктура** | Nginx 1.27, Docker Compose, Certbot | SSL Termination, HTTP/2, кеш статики до 6M, проксирование `/auth/` и `/game/`. |

## 2. Изоляция Phaser 3 и React UI

1. **Разделение зон ответственности:**
   - **React (`#root`):** Оверлеи, модальные окна (NiceModal), экран авторизации, верхний/нижний HUD, бейдж версии.
   - **Phaser (`#game-container`):** Игровой цикл, физика, спрайты, мини-игры («Поймай предмет», «Гонки», «Змейка», «Мемори»).
2. **Связывание слоев:**
   - Взаимодействие происходит **только** через Zustand сторы (`usePetStore`, `useCatchGameStore`) либо типизированные события шины (`EventBus`).
   - Запрещено прямое изменение DOM-элементов React из Phaser-сцен и наоборот.
3. **Управление памятью на мобильных устройствах:**
   - При смене или перезапуске сцен обязательно очищать слушатели событий (`this.events.off`, `input.off`), останавливать анимации и таймеры (`time.removeAllEvents()`).
   - Видеоэлементы персонажа должны освобождаться при анмаунте (`v.removeAttribute("src"); v.load()`).
4. **Специфика iOS / Safari (WebKit):**
   - **Прозрачные видео:** Источник **HEVC (`.mov`/`.mp4` с кодеком `hvc1`) ОБЯЗАН стоять первым** в `<video>`. WebM в Safari не поддерживает альфа-канал и отображает сплошной черный квадрат.
   - **Web Audio:** Аудиоконтекст в iOS стартует в suspended-состоянии. В `PreloaderScene` обязателен таймаут безопасности (fallback 3 сек), чтобы декодирование аудио не блокировало загрузку.

## 3. Бэкенд-архитектура и границы контекстов

1. **Модульность:**
   - `backend/auth-service/` — регистрация, OTP, PIN, выдача и отзыв токенов.
   - `backend/game-service/` — механики тамагочи (голод, мытье, сон, игра), инвентарь, награды.
   - `backend/shared/` — пул БД (`db.ts`), общие мидлвары авторизации, валидаторы, логгер.
2. **Запрет перекрестных импортов:**
   - Модули `auth-service` и `game-service` **не имеют права импортировать доменную логику друг друга напрямую**. Связывание разрешено только через слой хранения (БД), общие интерфейсы `shared` или межмодульные вызовы.
3. **Graceful Shutdown:**
   - Обработка `SIGTERM` и `SIGINT` с закрытием соединений пула `pg` и завершением текущих HTTP-запросов.

## 4. Безопасность и Авторизация

1. **Двухфакторная модель:**
   - **Фактор 1 (Родитель):** SMS OTP-код на номер телефона.
   - **Фактор 2 (Ребенок):** Фруктовый PIN-код (последовательность из 4 фруктов).
2. **Хранение фруктового PIN:**
   - ПИН-код категорически запрещено хранить в открытом виде.
   - Обязательно использование медленного хэширования **`bcrypt`** (work factor >= 10) с уникальной солью.
3. **Жизненный цикл токенов:**
   - **Access Token:** Короткоживущий JWT (15 минут), передается в заголовке `Authorization: Bearer <token>`.
   - **Refresh Token:** Долгоживущий токен (30 дней), хранится в БД / HttpOnly cookie.
   - **Refresh-Token Rotation:** При каждом обновлении токена старый Refresh Token отзывается, выдается новая пара.
   - **Token Blacklist:** Таблица `token_blacklist` с полями `(token, expires_at)` и индексом для мгновенной инвалидации при логауте.
4. **Защита от перебора (Rate Limiting):**
   - Строгий лимит попыток ввода SMS-кода и PIN-кода на уровне Express middleware (по IP и номеру телефона).

## 5. Серверный Античит (Game Economy)

1. **Принцип серверной авторитетности:**
   - Клиент является ненадежным источником. Клиент сообщает только факт начала, завершения и сырые игровые события (время сессии, набранные очки).
   - Сервер самостоятельно рассчитывает и подтверждает награду (монеты, опыт, изменение сытости/энергии).
2. **Валидация ограничений:**
   - Проверка физической осуществимости: минимальное время прохождения, максимальное количество монет в секунду.
   - Суточные лимиты наград и кулдауны между игровыми сессиями.
3. **Транзакционность:**
   - Все начисления валюты и изменения инвентаря выполняются внутри транзакций БД (`BEGIN ... COMMIT`) с предотвращением race conditions.

Подробнее: [references/security-and-anticheat.md](references/security-and-anticheat.md)

## 6. База данных и Миграции (PostgreSQL 17)

1. **Запрет DDL в рантайме:**
   - Никаких `CREATE TABLE IF NOT EXISTS`, `ALTER TABLE` внутри обработчиков запросов или старта приложения.
2. **Миграции:**
   - Все изменения схемы оформляются версионированными миграциями с обязательным скриптом отката (forward/rollback).
3. **Индексы:**
   - Обязательные индексы для частых выборок: `token_blacklist(token, expires_at)`, `users(phone)`.
4. **Очистка устаревших данных:**
   - Фоновая периодическая очистка протухших записей в `token_blacklist` (cron/worker).

## 7. PWA, Кеширование и Офлайн-стратегия

1. **Разделение политик кеширования:**
   - **Иммутабельные ассеты:** Скрипты, стили, аудио, спрайты, видео с хэшем контента в имени кешируются Nginx и Service Worker долгосрочно (`Cache-Control: public, max-age=15552000, immutable`).
   - **API и Авторизация:** Запросы к `/auth/*` и `/game/*` **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО кешировать** в Service Worker CacheStorage (`NetworkOnly`).
2. **Адаптивность под PWA Standalone:**
   - Учет iOS Safe Area Insets: `env(safe-area-inset-bottom)`, `100dvh` вместо `100vh`.

## 8. Стандарты для Детской Аудитории (Children-First & Privacy)

1. **Минимизация PII (152-ФЗ / COPPA):**
   - Запрещен сбор и хранение персональных данных детей (ФИО, email, геолокация, фото). Допустимы только имя питомца и номер телефона родителя.
2. **Логирование:**
   - Маскирование номеров телефонов (`+7***...`) и полное исключение PIN-кодов/токенов из логов сервера.
3. **Детский UX:**
   - Минимальный размер интерактивных элементов (touch target) — не менее **48×48px**.
   - Позитивные, нейтральные сообщения об ошибках («Давай попробуем еще раз!» вместо технических кодов).
   - Поддержка `prefers-reduced-motion` (отключение резких вспышек и тряски экрана).

## 9. Критерии готовности (Definition of Done)

Задача считается выполненной только при соблюдении следующих условий:

- [ ] **Typecheck:** Полное отсутствие ошибок TypeScript (`tsc --noEmit`).
- [ ] **Lint:** Код проходит проверку ESLint / Prettier без предупреждений.
- [ ] **Тесты:** Пройдены unit-тесты логики и integration-тесты API.
- [ ] **E2E Smoke:** Проверен критический путь (вход -> главный экран -> уход за питомцем -> мини-игра).
- [ ] **Кросс-платформенность:** Проверена корректность рендеринга на iOS (Safari, WKWebView) и Android (Chrome).
- [ ] **Nginx & Docker:** Конфигурация проверена (`nginx -t`), образы собираются без ошибок.
- [ ] **Версионирование и Changelog:** Инкрементирована версия в `package.json`, добавлен раздел в `CHANGELOG.md`, обновлен `tasks/todo.md`.
- [ ] **Чистая система:** Никаких установок глобальных пакетов в хостовую систему WSL.
